## 🔬 独立评审发现的缺陷与修复

评审子代理（`replay-design-review`，MiniMax-M2.7，31s）在实现并发进行时做了只读评审，发现 6 个真实缺陷，全部已修复：

| # | 缺陷 | 严重度 | 修复 |
|---|------|--------|------|
| 1 | `--n-samples`/`--noise` 被发出但 CLI 训练时硬编码 500/0.3 —— 会**静默训练出不同模型** | HIGH | 标志位不再发出；改为 warning + SDK 指引 |
| 2 | `random_state`/`max_iter`/`algorithm` 与 CLI 自身 kwargs 碰撞 → `TypeError` | HIGH | `CLI_HARDCODED_KWARGS` 检测 + warning |
| 3 | `max_depth=None` → `'None'` 字符串 → `int('None')` → `ValueError [E3003]` | MED | `_CLI_LOSSY_TYPES` 已含 `type(None)`，自动标记 |
| 4 | CLI `MLP` `max_iter=2000` vs SDK `max_iter=500` → CLI 无法复现 SDK 训练的 MLP | HIGH | `CLI_DIVERGENT_FAMILIES` 检测 + warning |
| 5 | `seed: null` → SDK 片段硬编码 `MLDB(seed=42)` —— "精确"配方但不是原跑 | MED | 改为 `MLDB()  # NOTE: no seed was recorded` |
| 6 | 数字字符串（如 `kernel="1"`）被 `parse_params` 静默转为 int → 不同模型且指纹不同 | MED | `_parse_params_value()` 忠实复刻 CLI 强制转换，检测静默重类型 |

**验证方式**：新增 2 个端到端测试，实际 `subprocess.run` 发出的 CLI 命令并断言返回码与错误信息。
