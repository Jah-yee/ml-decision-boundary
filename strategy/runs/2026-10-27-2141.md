## 3. 本轮主题决策

v13 DoD #1-#4 已全绿，CI 全绿，三个 PR 待 Merge。按 playbook「完成一个完整的小闭环」原则，本轮选择**不阻塞开发、但有真实用户价值**的遗留问题：

**v13 DoD #5 — Artifact Compatibility Layer**

理由：
1. v121 早场的迁移后验证报告了 **700 个不可加载的模型**（`AttributeError: Can't get attribute '__pyx_unpickle_CyHalfBinomialLoss'`）。
2. 上一轮已证明这与迁移无关（直接 `joblib.load(blob)` 同样失败；复制回旧版 per-model 布局用旧代码路径加载，报同样的错）。
3. 本轮把根因定位到了**字节级**：pickle 的 `STACK_GLOBAL` 操作码把 `sklearn._loss._loss.__pyx_unpickle_CyHalfBinomialLoss` 这个 Cython 内部名写进了字节流。sklearn 1.7.2 把它改名为公开的 `CyHalfBinomialLoss`，旧名消失 → 反序列化直接失败。
4. **产物字节本身没有任何问题，坏掉的只是"名字"。** 这是一个可修复的兼容性债务，且修复成本极低（一张别名表）。

## 4. 实现

### 4.1 `core/compat.py`（新，唯一实现源）

- 别名表 `_ALIASES`：`(module_path, legacy_name, current_name)` 三元组
  - `("sklearn._loss._loss", "__pyx_unpickle_CyHalfBinomialLoss", "CyHalfBinomialLoss")`
- `apply_shims()` — 导入时自动执行，幂等，不重复安装，模块缺失时静默跳过
- `installed_aliases()` — 返回当前活跃的别名表
- `is_compat_shim_active()` — 是否至少有一个别名生效
- `check_artifact(path)` — 单文件探针，诊断用途，**从不抛错、从不改文件**

### 4.3 `RegistryManager.health_check()`

三态分类，语义明确区分：
- `loadable` — 反序列化成功
- `no_artifact` — 只有元数据、从未存过产物（**不是损坏**，实测 6501 条）
- `unloadable` — 产物存在但读不出来（附失败原因分组）

### 4.4 测试

`tests/test_compat.py` — **23 个新测试**，覆盖：
- 别名表本身（幂等性、形状、激活状态）
- `check_artifact` 的三种输入（好文件 / 坏文件 / 缺失文件）
- **因果对照**：同一份产物，未 import `core.compat` → `AttributeError`；import 后 → 正常加载
- shim 不修改存储字节（`test_shim_does_not_modify_stored_bytes`）
- registry 健康审计的四个场景（空 / 可加载 / 元数据记录 / 不可加载）
- CLI 表面（`model health` / `--sample` / `--help` 列出 health）
- SDK 表面（`db.health()` / `db.compat_shims()`）

## 6. 事故与修复

**端口 5000 被占用导致 P3 误判 404。**
第一次 P3 验证时 `/api/provenance?coverage=1` 返回 404，但 `/api/health` 返回 200。排查发现：
- `web/server.py` 需要 `PYTHONPATH=.` 才能 import `core`（不是 `main.py --web` 启动）
- 端口 5000 被另一个进程占用，Flask 报 `Address already in use`，实际未启动
- `fuser -k 5000/tcp` 清端口后重新验证，coverage 端点正常返回 200 + 完整 summary

**教训**：P3 验证前先确认服务真的启动了，不要被"部分成功"误导。

## 7. 遗留（明确不做）

- 6501 条"元数据记录"没有产物。这不是 bug —— 这些记录注册时就没保存模型对象。**无法追补**，除非重新训练。
- `InconsistentVersionWarning` 仍然存在（13981 个产物带此警告）。这是**诚实提示**：产物是用 1.4.1 拟合的，用 1.7.2 加载，数值不保证逐位一致。本层只保证"能读"，不承诺"读出来一定一样"。
