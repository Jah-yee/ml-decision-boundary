## 关键发现

### 1. `git merge-tree` 的退出码不是冲突信号

第一版实现信任退出码 → 报告「mergeable: yes」→ **假阴性**，正好漏掉了它要抓的缺陷。

冲突必须从**输出**里解析：`CONFLICT` 标记 + 冲突路径列表。退出码在不同 git 版本/冲突类型间不一致。

### 2. 底部向上合并实际零冲突

实测验证：6/6 PR 按推荐顺序合并，**零冲突**。stack 本身可合并，但拓扑不线性（PR #66 分叉于 PR #63）。

### 3. 默认门禁 vs 严格门禁

- 默认：`mergeable` + `no_duplicate_payload` → 回答「能合并吗？」
- 严格：+ `linear` → 回答「已经准备好合并了吗？」
- 严格集合是默认集合的严格超集 → 单调性由构造保证
