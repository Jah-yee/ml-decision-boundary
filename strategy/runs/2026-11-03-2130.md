## 问题
PR #67 的 CI `quality-gates` job 报 `P1 — Pytest` FAILURE，3 条测试失败：
- `test_cli_json_output_is_parseable`
- `test_cli_gate_requirements_are_reported`
- `test_cli_strict_mode_adds_a_requirement`

**根因**：这三条测试直接对 `REPO_ROOT`（真实仓库）运行 `stack_topology_audit.py --json`，而该脚本内部调用 `gh pr list`。CI runner 上 `gh` 虽然安装了，但没有 `GH_TOKEN`，导致 `gh pr list` 返回 rc=4，脚本抛出 `StackAuditError`，退出码 2。测试期望退出码 0 或 1，实际是 2 → 失败。

## 修复
将 3 条 CLI 测试改为 **hermetic**（自给自足，不依赖网络/CI 环境变量）：

1. 新增 `_fake_gh()` 辅助方法：在 `tmp_path/bin/gh` 创建一个假 `gh` 脚本，对 `pr list` 返回 `[]`（空 PR 列表）
2. 用 `monkeypatch.setenv("PATH", ...)` 把假 `gh` 放到 PATH 最前面
3. 用 `_init(tmp_path / "repo")` 创建 throwaway repo 代替 `REPO_ROOT`
4. 3 条测试全部改为接受 `tmp_path` + `monkeypatch` 参数

**关键设计决策**：不给 CI 加 `GH_TOKEN`（安全风险），而是让测试自给自足。测试应该测代码逻辑，不是测环境。
